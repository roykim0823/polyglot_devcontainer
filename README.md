# polyglot_devcontainer

A reproducible, polyglot **VS Code Dev Container** that ships C++, Python,
and Rust toolchains pre-installed. Drop the two files in this repo
(`Dockerfile` + `devcontainer.json`) into any project's
`.devcontainer/` directory and you get a green quality-gate run on
day one — no per-project toolchain setup.

Originally extracted from
[`cmake_template`](https://github.com/cpp-best-practices/cmake_template);
designed to be the shared dev container for sibling templates
(`cmake_template`, `python_template`, `rust_template`) and any consuming
project.

## What's in the image

Built on `mcr.microsoft.com/devcontainers/cpp:2-ubuntu24.04`.

### C++ toolchain
- LLVM 19: `clang`, `clang++`, `clangd`, `clang-format`, `clang-tidy`,
  `clang-tools` (`scan-build`/`scan-view`), `lld`, `lldb`, `llvm-cov`,
  `libc++-dev`, …
- `cppcheck`, `iwyu` (include-what-you-use), `doxygen` + `graphviz`,
  `valgrind`, `shellcheck`, `ccache`
- `vcpkg` (shallow clone at `$VCPKG_ROOT=$HOME/vcpkg`)
- `mold` (fast linker), `musl-tools`, `libclang-dev`

### Python (via `uv`)
- Python 3.12 and 3.13 pre-installed (older minors via
  `uv python install` on demand)
- uv tools (each in its own isolated env): `cpplint`,
  `cmakelang` (provides the `cmake-format` and `cmake-lint`
  executables), `pre-commit`, `conan`, `ruff`, `mypy`,
  `bandit[toml]`, `pip-audit`, `commitizen`

### Rust (via `rustup`)
- Stable channel + components (`rustfmt`, `clippy`, `rust-src`,
  `rust-analyzer`, `llvm-tools-preview`)
- Cargo extensions: `cargo-nextest`, `cargo-llvm-cov`, `cargo-audit`,
  `cargo-deny`, `cargo-machete`, `cargo-msrv`, `cargo-watch`,
  `cargo-edit`, `cargo-outdated`
- `mdbook` for narrative docs

### Editor / tooling
- Node.js 22 + LSP servers: `typescript-language-server`, `pyright`,
  `vscode-langservers-extracted`, `eslint`
- VS Code extensions baked into `devcontainer.json`: clangd, lldb,
  ruff, pylance, rust-analyzer, eslint, prettier, editorconfig,
  cspell

## How to use

Three patterns, in order of friction.

### 1. Copy the two files into your project

```bash
cd <your-project>
mkdir -p .devcontainer
curl -fsSL -o .devcontainer/Dockerfile        https://raw.githubusercontent.com/<your-org>/polyglot_devcontainer/main/Dockerfile
curl -fsSL -o .devcontainer/devcontainer.json https://raw.githubusercontent.com/<your-org>/polyglot_devcontainer/main/devcontainer.json
```

Then open in VS Code → **Dev Containers: Reopen in Container**. No
ongoing link to upstream — you get a frozen snapshot, edit freely.

### 2. Reference as a git submodule

When you want to track upstream improvements:

```bash
cd <your-project>
git submodule add https://github.com/<your-org>/polyglot_devcontainer.git .devcontainer/upstream
```

Then point your `.devcontainer/devcontainer.json` at the submodule:

```jsonc
{
    "name": "myproject",
    "build": {
        "dockerfile": "upstream/Dockerfile",
        "context": "upstream"
    },
    // ... your runArgs / mounts / extensions ...
}
```

`git submodule update --remote .devcontainer/upstream` pulls the
latest version of the polyglot container.

### 3. Pre-built image from a registry

If you publish the built image (e.g. to GitHub Container Registry),
consumers can skip building entirely:

```jsonc
{
    "name": "myproject",
    "image": "ghcr.io/<your-org>/polyglot-devcontainer:latest"
}
```

This is the fastest container start (~10 s) but requires you to set
up a build-and-publish workflow (a starter is provided in
[`.github/workflows/publish.yml`](.github/workflows/publish.yml) —
see "Publishing" below).

## Try it locally

```bash
git clone https://github.com/<your-org>/polyglot_devcontainer.git
cd polyglot_devcontainer
docker build -f .devcontainer/Dockerfile -t polyglot-devcontainer:dev .devcontainer
docker run -it --rm polyglot-devcontainer:dev bash
# Inside container — sanity-check the toolchains:
clang --version              # → clang 19.x
uv --version
uv python list               # → 3.12, 3.13
rustc --version              # → 1.85+
cargo nextest --version
mdbook --version
```

## Build args

Override at build time with `--build-arg <key>=<value>`:

| Arg | Default | Purpose |
| --- | --- | --- |
| `LLVM_VERSION` | `19` | LLVM/Clang major version. Must match a `clang-N` package in Ubuntu 24.04 universe. |
| `NODE_VERSION` | `22` | Node.js major version (used for the LSP servers + commitlint). |
| `USERNAME` | `vscode` | Non-root user the container runs as. |

## Updating

The container's pinned versions live in `Dockerfile`. Bump:
- LLVM via `LLVM_VERSION` build arg + the `clang-tools-N`,
  `lld-N`, etc. apt packages.
- Rustup pulls "stable" — gets the latest stable on each rebuild.
- Python: edit `uv python install 3.X 3.Y`.
- Cargo extensions: edit the `cargo install --locked` block.

`devcontainer-lock.json` (auto-generated by VS Code Dev Containers
tooling) pins the `features:` entries — regenerate by running **Dev
Containers: Rebuild Container** in VS Code, then commit the result.

## Publishing (optional)

To publish a pre-built image to GitHub Container Registry, add a
workflow like:

```yaml
# .github/workflows/publish.yml
name: Publish
on:
  push:
    branches: [main]
    paths: [".devcontainer/Dockerfile", ".devcontainer/devcontainer.json"]
permissions: { contents: read, packages: write }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v5
        with:
          context: .devcontainer
          file: .devcontainer/Dockerfile
          push: true
          tags: ghcr.io/${{ github.repository_owner }}/polyglot-devcontainer:latest
```

Once published, downstream projects can use pattern #3 above.
